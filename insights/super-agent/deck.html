금융사의 위기

2-1위기의 구조

2-2이미 본 영화

규제라는 방패도 접점의 상실은 막지 못했습니다

통신산업의 경험은 겸허하게 참고할 가치가 있습니다. 물론 금융과 통신은 다릅니다만, 구조적 유사성은 부인하기 어렵습니다.

통신사 (2007~)

스마트폰 이후의 통신사

고객 접점(문자·통화·미디어)을 앱 생태계에 내주고,

"트래픽을 나르는 인프라"로 물러났습니다.

메신저가 문자를, 스트리밍이 미디어를, 앱스토어가 유통을 가져갔고, 수익은 정체되고 밸류에이션은 유틸리티 수준에 머물렀습니다.

은행 (2026~?)

에이전트 이후의 은행?

고객 접점(조회·이체·상담·추천)을 OS 에이전트에 내준다면,

"자본을 나르는 인프라"로 물러날 수 있습니다.

McKinsey도 같은 우려를 내놓았습니다. "3~5년 내 AI 에이전트가 뱅킹 상호작용의 기본 채널이 되면, 리테일 은행은 고객관계의 주도권을 잃을 수 있다."

2-3문 앞에 온 신호

카드 네트워크는 이미 에이전트에게 지갑을 쥐여줬습니다

인프라 표준은 은행을 기다려주지 않습니다. 레일은 지금 깔리고 있습니다.

VISA

Visa Intelligent Commerce

"AI-Ready Card". 카드정보를 토큰화된 자격증명으로 대체하여, 특정 에이전트에게 한도 내 결제 권한을 위임. 100여 개 파트너와 출시.

MASTERCARD

Agent Pay → "Agent Pay for Machines"

Agentic Token 기반. 2026년 미국 전체 카드홀더로 확대. 기계간(M2M) 초고속 마이크로결제까지 선언했습니다.

GOOGLE 진영

AP2 (Agent Payments Protocol)

Visa·Mastercard·Stripe가 모두 참여. 에이전트의 결제 의사를 검증하는 '위임 증명' 표준이 만들어지고 있습니다.

STRIPE

에이전트 전용 지갑 · 1회용 카드

에이전트가 스스로 지갑을 보유하고 1회용 카드를 발급하며 실시간 마이크로페이먼트를 처리합니다. '에이전트가 고객'인 시대의 인프라입니다.

🛡

신뢰와 책임 (Trust)

돈이 오가는 대행에는 '틀렸을 때 책임지는 주체'가 필요합니다. 예금자보호·금융규제·수십 년의 신뢰는 하루아침에 만들어지지 않습니다.

◈

돈의 데이터 (Data)

수입·지출·자산·부채·보험. 고객의 재무 전체를 아는 드문 사업자입니다. 에이전트의 품질은 컨텍스트의 품질이 좌우합니다.

⚖

실행 라이선스 (License)

추천은 누구나 할 수 있지만, 계좌 개설·대출 실행·보험 인수는 라이선스 사업자만 가능합니다. 마지막 1마일은 우리에게 있습니다.

CASE 1미국 · JPMorgan Chase

슈퍼에이전트는 조직 운영 방식에서 출발합니다

무엇을 했는가

  • 사내 LLM Suite를 전 직원에 배포 → 에이전트 오케스트레이션으로 확장
  • 기업 자금관리(Treasury)에 에이전틱 AI 적용, 현금흐름 예측·집행 자동화
  • 결제 부문은 에이전틱 커머스의 신뢰·책임(liability) 모델을 선제적으로 설계 중

참고할 점

"고객용 챗봇 하나"가 아니라 회사 전체를 에이전트 중심으로 바꾸는 접근입니다.

내부에서 에이전트를 대규모로 운영해 본 조직이라야, 고객의 돈을 맡는 에이전트도 안전하게 내놓을 수 있습니다.

→ 순서: 내부 검증 → 고객 대면 → 개방

어드바이저 1인의 서비스 커버리지가 크게 늘며 사람 + 에이전트 하이브리드 자문 모델이 자리잡았습니다.

2단계, 외부: 에이전트에게 퍼널 개방 (2026)

수천 개 기업의 외부 AI 에이전트가 자사 자산관리 퍼널로 직접 진입하도록 개방했습니다. 월가에서 손꼽히는 이른 시도입니다 (CNBC).

"에이전트가 고객을 데려오는 시대"의 유통망을 선점하려는 포석으로 읽힙니다.

CASE 4 · 5유럽 · NatWest & Klarna

목표는 비용이 아니라 고객 성과와 신뢰여야 합니다

NATWEST (영국)

OpenAI와의 전략 제휴

디지털 어시스턴트 Cora를 단순 챗봇에서 계좌 실행형 에이전트로 진화시키는 중입니다. 사기 대응·취약고객 지원까지 에이전트화.

포인트는 분업입니다. 모델은 빌리고, 고객관계는 지킨다.

무엇을 짓고, 고객 삶의 어디에 자리 잡을 것인가

4-1레퍼런스 아키텍처 (개념)

차별점은 지능이 아니라 신뢰 레이어에 있습니다

5개 레이어 가운데 ②지능은 시간이 지나면 평준화됩니다. ④위임·한도·인증·감사가 금융 에이전트의 해자입니다.

① 경험 레이어 Surface
우리 앱 (대화형 홈)음성 · 메신저차량 · 워치 · IoT타사 에이전트 (ChatGPT·Siri·Gemini)
② 슈퍼에이전트 Orchestrator
의도 이해 · 계획 수립고객 컨텍스트 메모리전문 에이전트 라우팅승인·확인 UX
③ 전문 에이전트 Domain Agents
자산관리대출·심사보험 설계카드·지출라이프 (여행·주거·차)외부 제휴 에이전트 (A2A)
④ 신뢰 레이어 Trust & Control
위임장 · 한도 관리 (Mandate)본인·에이전트 인증 (AP2 등)이상거래 탐지감사 로그 · 설명가능성규제 준수 게이트
⑤ 실행 · 데이터 Core & Data
그룹 통합 고객 데이터 (Customer 360)계열사 코어 API (계좌·대출·보험·카드)MCP 도구 서버마이데이터 · 외부 데이터

4-3레퍼런스 아키텍처 (요청 흐름)

한 번의 요청이 신뢰 게이트를 통과하는 경로입니다

어떤 표면에서 들어와도, 어떤 에이전트가 수행해도, 돈이 움직이는 실행은 반드시 신뢰 게이트를 지나갑니다.

4-4그래서, 우리는 무엇을 해야 하는가

결론은 하이퍼스케일러와의 동행, 단 조건부입니다

모든 것을 자체 구축하기에는 늦고, 모든 것을 맡기기에는 위험합니다. '빌릴 것'과 '지킬 것'의 경계가 전략의 전부라고 생각합니다.

빌릴 것 (하이퍼스케일러에서)
  • 모델과 에이전트 런타임: 모델은 6개월마다 세대교체됩니다. 직접 만들 영역이 아닙니다
  • 에이전트 인프라: 게이트웨이·메모리·관측성은 이미 관리형 서비스로 상품화되었습니다
  • 보안·컴플라이언스 빌딩블록: 암호화·감사·격리는 검증된 것을 씁니다
지킬 것 (반드시 내재화)
  • 고객 데이터와 컨텍스트 메모리: 에이전트 품질의 원천이자 협상력의 원천입니다
  • 신뢰 레이어의 정책: 위임·한도·책임 규칙은 우리의 라이선스와 직결됩니다
  • 도메인 에이전트의 노하우: 심사·설계 로직은 경쟁력 그 자체입니다

유의점 세 가지: ① 멀티모델 전략으로 특정 모델 종속 회피 ② 국내 클라우드·망분리 규제와 데이터 주권 검토 선행 ③ 계약에 이그레스(이전) 조건 명시

4-5신뢰 레이어, 조금 더 들어가 보면

"얼마나 똑똑한가"보다 "얼마나 맡길 수 있는가"

위임은 기능이 아니라 관계입니다. 신뢰가 쌓이는 만큼 권한을 올리는 설계가 락인(Lock-in)을 만든다고 봅니다.

4-6임베디드 전략

정답은 고객이 있는 모든 곳입니다

① OWN, 직접 접점

슈퍼앱을 에이전트 홈으로

메뉴 그리드를 대화·카드형 '오늘의 재무 브리핑'으로. 자산관리·대출·보험이 하나의 대화 안에서 완결됩니다.

참고: Alipay 支小宝, NatWest Cora

② EMBED, 타사 접점 속으로

외부 에이전트의 '공식 금융 도구'로

ChatGPT·Siri·Gemini가 금융 과업을 만나면 우리 에이전트를 호출하도록 MCP/A2A·AP2로 입점합니다. 새로운 유통 채널입니다.

참고: Morgan Stanley의 퍼널 개방

③ AMBIENT, 삶의 순간 속으로

이벤트가 곧 접점

이사·출산·이직·차 구매 같은 라이프 이벤트를 감지해, 고객이 부르기 전에 준비된 제안으로 나타납니다.

비금융 제휴 데이터 + 마이데이터

어느 접점에서 불려도 같은 에이전트, 같은 기억, 같은 신뢰. 이것이 임베디드 전략의 요체입니다.

4-7고객의 하루, 통합 시나리오

고객이 체감하는 것은 해결된 목적 1개입니다

"오사카 여행 준비해줘". 이 한 마디의 백스테이지를 그려보면 이렇습니다.

07:30 · 감지캘린더의 여행 일정 감지
→ 여행 모드 제안 (Ambient)
→
07:31 · 계획예산 분석 → 환전 최적 시점,
여행자보험 3안 설계
→
07:32 · 승인"보험 2안, 환전 진행해줘"
→ 한도 내 즉시 실행 (Lv.3)
→
여행 중 · 자율현지 결제 최적 카드 자동 선택,
이상거래 실시간 차단 (Lv.4)

은행(환전·계좌) + 보험(여행자보험) + 카드(결제·혜택) + 비금융(항공·숙소 제휴)이 하나의 대화로 완결됩니다. 계열사 앱 4개를 열 일이 없습니다.

4-8실행 로드맵

기술의 순서가 아니라 신뢰의 순서입니다

내부 검증 없이 고객 위임은 없고, 고객 위임 없이 생태계 개방은 없다고 생각합니다.

PHASE 1 · ~1년

기반: 내부부터 에이전트화

  • 직원용 에이전트로 역량·거버넌스 축적 (JPM 모델)
  • 그룹 Customer 360 + 코어 API의 도구화 (MCP)
  • 신뢰 레이어(위임·한도·감사)의 선행 구축
PHASE 2 · 1~2년

전환: 접점을 에이전트로

  • 슈퍼앱 홈 = 대화형 에이전트 (Lv.1→3)
  • 자산관리·대출·보험 도메인 에이전트의 통합
  • 라이프 이벤트 기반의 선제 제안 시작
PHASE 3 · 2~3년

확장: 생태계의 금융 허브

  • 외부 에이전트(OS·커머스)에 공식 입점 (MS 모델)
  • AP2 등 에이전트 결제 표준에 참여
  • 한도 내 자율 실행(Lv.4)으로 위임 심화
4-9성공의 척도

"체류시간이 줄어드는 것"이 성공일 수 있습니다

고객의 시간을 아껴줄수록 위임은 깊어집니다. 측정하는 것이 바뀌어야 조직이 바뀝니다.

UI NATIVE KPI (어제)
  • MAU / DAU
  • 체류시간, 화면 방문 수
  • 배너 클릭률 (CTR)
  • 상품별 가입 전환율
AGENT NATIVE KPI (내일)
  • 위임률: 자동실행을 허용한 고객 비율
  • 과업 완결률: 목적을 끝까지 해결한 비율
  • 고객 성과: 절약액·수익률·보장 공백 해소
  • 에이전트 경유 AUM/여신: 새 유통망의 성과
4-10리스크 관리

신뢰 레이어 투자는 비용이 아니라 차별화 자산입니다

빨리 가되 무너지지 않으려면, 네 가지 리스크를 처음부터 설계에 넣어야 합니다.

리스크 1 · 품질 역풍 (Klarna의 교훈)

비용절감 목표의 AI는 신뢰를 잃습니다 → 고객 성과 KPI로 설계하고, 어려운 순간에는 사람으로 즉시 연결.

리스크 2 · 책임 공백 (Liability)

에이전트가 잘못 실행하면 누가 책임지는가, 업계 표준은 아직 미확정 → 위임장·한도·로그로 책임의 경계를 먼저 계약화.

리스크 3 · 규제 · 설명가능성

금소법·적합성 원칙은 에이전트에도 적용됩니다 → 모든 추천·실행에 근거 기록과 설명 UI를 기본 탑재.

리스크 4 · 보안 · 에이전트 사칭

프롬프트 주입·사칭 공격이 에이전트를 노립니다 → 에이전트 인증(토큰화 자격증명)과 이상행동 탐지를 신뢰 레이어에 내장.

다행히 그 자격, 신뢰 · 데이터 · 라이선스는 이미 여러분의 손에 있습니다.
